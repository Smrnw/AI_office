# AI Office

[English](README.md) · **Русский**

Команда ИИ-агентов в пиксельном офисе. Вы описываете проект в чате, руководитель разбивает его на
задачи, разработчики пишут код, тестировщик проверяет, а автопроверка открывает результат в настоящем
браузере, гоняет тесты и ищет уязвимости. Всё видно на канбане и в живом офисе, где каждый агент
сначала доходит до своего стола и только потом садится за работу.

![AI Office](docs/screenshots/main-ru.png)

## Возможности

- **Настоящая команда.** Руководитель, разработчики, тестировщики и специалисты: дизайнер интерфейсов,
  DevOps, технический писатель, специалист по безопасности. Каждый делает свою работу, специалисты
  в первую очередь берут свои файлы.
- **Любая нейросеть.** Google Gemini, Anthropic, OpenAI, OpenRouter, Ollama и любой OpenAI-совместимый
  API. Встроенный демо-провайдер работает без ключей и интернета.
- **Автопроверка.** Синтаксис всех файлов, автотесты в одноразовой копии (в Docker без сети, если он
  есть), страницы в Edge/Chrome — ошибки консоли, незагрузившиеся файлы, нажатия кнопок, скриншоты
  компьютера и телефона, которые оценивает нейросеть, и проверка безопасности (секреты в коде, XSS,
  SQL-инъекции, `eval`, bandit). Найденное само уходит разработчикам на доработку.
- **Автопилот.** `/auto <цель>` — руководитель превращает цель в требования и ставит задачи кругами,
  пока цель не достигнута, в пределах лимитов на круги, токены и время. Перед каждым кругом
  сохраняется версия проекта, откатиться можно из меню проекта.
- **Офис управляет собой сам.** Нанимает временных сотрудников, когда растёт очередь, и специалистов
  под их файлы, отпускает их после работы и ставит новые столы, когда мест не хватает (после того
  как вы обставили офис).
- **Проекты и история.** Каждый проект в своей папке со своим Git-репозиторием (ставить Git не нужно):
  коммит на каждую принятую задачу, автор — агент.
- **Уведомления.** Telegram и почта: проект готов, автопилот закончил, ошибки, вопросы команды.
  Ответьте боту в Telegram — сообщение уйдёт прямо в чат команды.
- **Офис под себя.** Ничего готового: системный промпт каждой роли вы пишете сами, а офис обставляете
  в редакторе планировки (зоны, мебель, столы). Редактор внешности агентов, светлая и тёмная темы,
  русский и английский интерфейс.
- **Обычные файлы, без базы данных.** Всё хранится в папке `data/` рядом с кодом.

## Быстрый старт

Скачайте код: **Code → Download ZIP** на [странице проекта](https://github.com/Smrnw/AI_office) и распакуйте, или

```bash
git clone https://github.com/Smrnw/AI_office.git
```

### Windows

1. Поставьте [Python 3.10+](https://www.python.org/downloads/) (или позвольте установщику сделать это через winget).
2. Дважды щёлкните **`install.bat`**. Он создаст `.venv`, поставит зависимости, добавит ярлык
   **AI Office** на рабочий стол и в «Пуск» и откроет офис в браузере.
3. Мастер настройки спросит название офиса, язык, нейросеть, папки и состав команды, а для каждой
   нанимаемой роли попросит написать системный промпт — готовых нет. Модель «Демо» позволяет
   попробовать без API-ключа. Затем откроется редактор планировки: офис пустой, расставьте столы и зоны.

Дальше офис запускается ярлыком или `start.bat`. Сервер работает в свёрнутом окне; закройте его,
чтобы остановить офис.

### Linux (Docker)

```bash
sudo ./deploy/install.sh            # только для этой машины: http://127.0.0.1:8080
sudo ./deploy/install.sh --lan      # доступ из локальной сети (с токеном)
```

Скрипт при необходимости ставит Docker, генерирует токен доступа, собирает образ и печатает ссылку
для входа. Управление: `pixel-office status | logs | restart | stop | url | backup`.

### Вручную

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip
.venv/bin/python -m pixel_office               # http://127.0.0.1:8080
```

Проверка в браузере использует установленный Edge или Chrome. Если их нет, выполните
`python -m playwright install chromium`.

## Как пользоваться

| В чате | Что произойдёт |
|---|---|
| Первое сообщение в «Проект» | Новый проект: план, задачи, код, ревью, автопроверка |
| Любое следующее | Доработка текущего проекта |
| `@Coder_1 как устроена форма?` | Отвечает названный агент |
| `/new <идея>` | Новый проект с чистой доской |
| `/auto <цель>` | Автопилот доводит проект до цели |
| `найми дизайнера` | Руководитель берёт постоянного сотрудника (для роли нужен ваш промпт) |

Карточки канбана перетаскиваются между колонками — например, обратно в «Очередь» с комментарием для
агента. Проект переключается кликом по его названию в шапке; там же автопилот, версии проекта и
история Git.

## Настройки

Настройки — в интерфейсе (**☰ → Настройки**), сохраняются в `data/config.json`. Параметры сервера
задаются переменными окружения или файлом `.env` (образец — `.env.example`):

| Переменная | Что задаёт |
|---|---|
| `PIXEL_OFFICE_DIR` | Папка данных. По умолчанию `data/` рядом с кодом |
| `PIXEL_OFFICE_HOST`, `PIXEL_OFFICE_PORT` | Адрес и порт. По умолчанию `127.0.0.1:8080` |
| `PIXEL_OFFICE_TOKEN` | Токен доступа. Обязателен, если сервер слушает не localhost |
| `PIXEL_OFFICE_ALLOWED_HOSTS` | Дополнительные имена хоста, например `office.lan` |
| `<ID_ПРОВАЙДЕРА>_API_KEY` | Ключ провайдера из окружения вместо `config.json` |

В `data/` лежит всё: конфиг с API-ключами, задачи, переписка, код проектов, версии, отчёты проверок
и журнал. Резервная копия — копия этой папки. **Никогда не публикуйте `data/`.**

## Безопасность

Сервер рассчитан на localhost или доверенную сеть. Он проверяет заголовок `Host` (DNS rebinding),
принимает изменяющие запросы только со своей страницы и с особым заголовком (CSRF), не запускается
на сетевом адресе без токена, держит API-ключи, токен бота и пароль почты только на сервере и
открывает сгенерированные страницы в песочнице CSP. Агенты пишут только внутрь рабочей папки и никогда
в `.git`; хуки Git не запускаются.

Код проекта выполняет только автопроверка, и только в одноразовой копии. Без Docker это обычный
процесс с таймаутом и пустым окружением — не полноценная песочница. Если это важно, выберите
«Только в Docker» в *Настройки → Проверка*. Подробности — [SECURITY.md](SECURITY.md).

## Разработка

```bash
.venv/bin/python -m pytest
```

Тесты гоняют всю команду на демо-провайдере, включая проверку в браузере.

```
pixel_office/   бэкенд (FastAPI): агенты, проверки, клиенты нейросетей, API, хранение
static/         фронтенд без сборки: ES-модули, офис на canvas, перевод интерфейса
deploy/         установщики для Windows и Linux
tests/          pytest
docs/           скриншоты и текст для страницы на GitHub
```
